# 技術選定と実装

Daybreakは、操作と音声をブラウザ、認証・保存・達成判定をCloudflare Workersに置く構成です。ミッション画面はアラーム起動と同時に表示します。動画の判定結果を待ってからミッション画面を開く設計ではありません。停止・スヌーズの権限はサーバーの判定が決めます。

## 採用技術と理由

### 画面と開発環境

| 技術 | 採用した理由・担当する処理 |
| --- | --- |
| React 19 / React DOM | アラーム一覧、編集ダイアログ、録画・判定・達成の状態をコンポーネントとして管理するため。カメラや音声の開始・終了を画面のライフサイクルへ結び付けます。 |
| TypeScript | アラーム、セッション、API応答をブラウザとWorkerで共有し、状態名やデータの取り違えをビルド時に検出するため。外部入力の安全性は別途ランタイムで検証します。 |
| Vite / `@vitejs/plugin-react` | Reactの開発時更新と静的ビルドを簡潔に行い、成果物をWorkers Static Assetsへそのまま配信するため。アラーム操作の中心はクライアントなので、SSRを前提としません。 |
| npm / lockfile | フロントとWorkerの依存を1つのプロジェクトで管理し、`npm ci` で同じ依存関係を再現するため。 |
| Motion | ダイアログや画面遷移、リストの配置変更、ばねを使ったフリックと戻り動作を統一するため。距離・速度のしきい値を超えたときだけ操作します。 |
| CSS | 白い半透明面、`backdrop-filter`、境界のハイライト、影、背景の光を組み合わせ、Liquid Glassを意識した表現をWebで実装するため。AppleのネイティブLiquid Glass APIを使っているわけではありません。 |
| Lucide React | アラーム・水・コーヒー・運動・設定の線画アイコンの形と太さを揃えるため。画像の取得待ちを増やさず、SVGとして表示します。 |
| DM Sans / `@fontsource-variable/dm-sans` | 時刻と欧文の見え方を揃えるため。フォントをビルドへ含め、外部フォントサービスへの実行時通信を避けます。日本語にはOSのフォントを使います。 |
| 全画面スケルトン | アプリ起動時の設定・アカウント・保存済み情報の取得中に、最終画面に近い骨格を表示するため。ミッション起動時に全画面ロードを挟んで開始を遅らせません。 |
| Web App Manifest / SVGアイコン | 対応ブラウザでホーム画面から開ける表示設定とアプリアイコンを用意するため。Service Workerによるオフライン判定やOSアラームは実装していません。 |
| localStorage | 未ログイン時の端末内アラーム設定を保存するため。データのバージョンと値を検証して読み込みます。認証トークンは入れません。 |

バージョンの正確な解決結果は `package-lock.json`、採用する範囲は `package.json` が管理します。

### アラーム・カメラ

| 技術 | 採用した理由・担当する処理 |
| --- | --- |
| Web Audio API | 音声ファイルのダウンロードを待たずにアラーム音を生成し、録画中の音量も調整するため。就寝モードを押す操作でAudioContextを有効にします。 |
| Screen Wake Lock API | 前面表示中の画面消灯を抑止するため。未対応・拒否・解除時には画面上の状態で知らせます。OSによる強制停止を回避できるAPIではありません。 |
| `Date` / `Intl` / タイマー | 時刻と曜日を計算し、保存したタイムゾーンでサーバー側も発生時刻を検証するため。一定の遅延を拾い、同じ発生を二重に鳴らさないよう管理します。 |
| `getUserMedia` | 端末カメラの映像をユーザーの許可に基づいて取得するため。マイクは要求しません。 |
| MediaRecorder | ブラウザが対応するWebMまたはMP4で動画を記録するため。ファイル選択による既存動画の提出を画面から受け付けず、その場の撮影に限定します。 |
| Canvas / JPEG | 録画と同時に低解像度フレームを取得し、順番にサーバーへ送るため。サーバーの受信時刻・連番のチェックを補助します。 |
| `performance.now()` / Visibility API / MediaStreamTrackイベント | 録画時間を測り、画面が隠れた、カメラが止まった、フレーム送信が失敗した場合に録画を無効にするため。MediaRecorderのチャンク数を時計代わりにはしません。 |
| Pointer操作・キーボード操作 | 達成後に左右のフリックを提供し、矢印キーでも同じ操作ができるようにするため。単なるクリックは停止へ変換しません。 |

ブラウザはバックグラウンドのタイマーや音声を停止でき、Wake Lockも解除できます。したがって、本アプリの動作範囲は画面を開いた状態でのアラームです。[Chromeのライフサイクル説明](https://developer.chrome.com/docs/web-platform/page-lifecycle-api)、[音声の自動再生制限](https://developer.mozilla.org/en-US/docs/Web/Media/Guides/Autoplay)、[MediaRecorderの時刻上の注意](https://developer.mozilla.org/en-US/docs/Web/API/MediaRecorder/dataavailable_event) を設計上の制約としています。

### API・認証・保存

| 技術 | 採用した理由・担当する処理 |
| --- | --- |
| Cloudflare Workers | ユーザー指定のCloudflareを基盤に、API、認証、動画処理の呼び出し、判定結果の確定を同じ実行環境へまとめるため。秘密値をブラウザへ渡しません。 |
| Workers Static Assets | Viteの `dist` をAPIと同じオリジンで配信し、認証Cookieと送信元の扱いを簡潔にするため。静的配信のヘッダーは `public/_headers` で設定します。 |
| Hono | Workersの標準Request/Responseに沿ってルートと共通処理をまとめるため。認証と送信元検証をAPIへ適用します。 |
| Zod | API入力とAI出力の型・範囲・必須フィールドを実行時に検証するため。追加フィールドや不完全なAI応答をそのまま採用しません。 |
| Google OAuth 2.0 / OpenID Connect | ログインをGoogleだけに統一し、アプリ側でパスワードを保有しないため。Authorization Codeフローを使い、`openid email profile` を取得します。 |
| PKCE / state / nonce | 認可コード、ログイン要求、IDトークンを開始したログイン処理に対応付けるため。stateはブラウザCookieと照合し、フローは一度だけ使用できます。 |
| jose | Googleの公開鍵を使い、IDトークンの署名・発行者・対象クライアント・有効期限を検証するため。アカウントのキーにはメールアドレスではなくGoogleの `sub` を使います。 |
| Secure / HttpOnly / SameSite Cookie | ブラウザJavaScriptから認証トークンを読み取れない形でセッションを送るため。DBにはトークンのSHA-256ハッシュを保存します。 |
| Web Crypto | セッション・チャレンジ用の乱数、PKCEチャレンジ、証拠の重複検出ハッシュを作るため。独自の暗号方式は追加しません。 |
| Cloudflare D1 / SQLite / SQL migrations | ユーザー、アラーム、セッション、ミッション状態、履歴を関係付きで保存するため。条件付き更新と一意制約で、二重判定・二重解除・同時チャレンジを制御します。 |
| D1の一時BLOB保存 | R2が設定されていない環境でも、元動画を非公開で保持してサーバー処理できるようにするため。動画を1MiB単位に分割し、メモリ使用を抑えるため順番に書き込みます。全チャンクの書き込み後にのみ読み出し可能にし、失敗時は部分データを削除します。長期動画保管を目的とした構成ではありません。 |
| 任意のCloudflare R2 | バケットを用意できる環境で動画・画像をオブジェクトストレージへ保存するため。`EVIDENCE` バインディングがある場合はこちらを優先します。公開URLは必要ありません。 |
| Cron Triggers | 放置された証拠と期限切れ状態・認証情報を定期清掃するため。端末のアラームを鳴らすスケジューラとしては使用しません。 |
| Wrangler / Workers Types | D1 migration、Secret設定、ローカルWorker、Cloudflareへのデプロイを同じ設定で管理し、バインディングの型を確認するため。 |
| Workers Observability | 障害調査のために有効化しています。アプリのエラーログにはリクエスト本文、Cookie、トークン、動画を出力しない実装です。 |

Googleの認証方式は [公式Webサーバーフロー](https://developers.google.com/identity/protocols/oauth2/web-server) と [IDトークンの検証要件](https://developers.google.com/identity/gsi/web/guides/verify-google-id-token) に基づきます。静的コンテンツとWorkerのレスポンスは別の配信経路なので、それぞれのヘッダー設定が必要です。[Static Assetsのヘッダー](https://developers.cloudflare.com/workers/static-assets/headers/) を参照してください。

### 動画の達成判定

| 技術 | 採用した理由・担当する処理 |
| --- | --- |
| Cloudflare Media Transformations | 元動画からサーバー側で時間順の画像を取り出すため。クライアントが選んだ画像だけを見て合格させる構成を避けます。Workerの `MEDIA` バインディングを使います。 |
| Workers AI | ユーザー指定のAI実行基盤。Workerからバインディング経由で推論を呼び出し、ブラウザにAI用の鍵を渡しません。 |
| `@cf/meta/llama-4-scout-17b-16e-instruct` | 画像とテキストを入力できるため。手の動作、飲み物や身体の動き、順番、回数を時系列画像から評価させます。 |
| JSON Schema + Zod + サーバー条件 | AIの自由文を操作権限へ変換しないため。必要条件がすべて揃った構造化応答だけを処理し、不確実・不正形式・接続失敗では解除しません。 |

Workers AIへMP4を直接渡す実装ではありません。Media Transformationsで抽出した画像を、時刻のラベルとともに順序付きで渡します。画像入力はbase64 data URIです。[Scoutのモデル仕様](https://developers.cloudflare.com/workers-ai/models/llama-4-scout-17b-16e-instruct/) と [公式スキーマ](https://github.com/cloudflare/cloudflare-docs/blob/production/src/content/workers-ai-models/llama-4-scout-17b-16e-instruct.json) を参照してください。

Media TransformationsのWorkersバインディングは公開ベータです。遅延・利用条件・制限の変更があり得るため、公開環境での検証が必要です。[公式バインディング資料](https://developers.cloudflare.com/stream/transform-videos/bindings/) を参照してください。

## ミッションの処理

1. 前面でアラーム時刻を検知すると、すぐにミッション画面へ切り替えます。
2. サーバーはログイン、アラームの所有者、発生時刻、未解決の状態を確認し、指の本数を含む動作の指示と期限を発行します。
3. ユーザーの操作でカメラを開き、最初の指の動作、指定ミッション、最後の手のひらを続けて撮影します。
4. 画像を連番で送信し、サーバーの受信時刻と順番を記録します。画面非表示・カメラ停止・送信エラーを検出した録画は無効にします。
5. 元動画をアップロードします。サイズ、形式、時間、重複を確認し、サーバー側で画像を抽出します。
6. AIが動作・順番・連続性・不自然な再撮影を評価します。サーバーは構造・信頼度・回数などを確認して状態を確定します。
7. 合格時だけ停止・スヌーズ操作を受け付けます。発生時刻と有効期限を確認し、権限を一度だけ消費します。スヌーズ後は新しいミッションが必要です。
8. 元動画と画像を稼働中の保存先から削除し、結果の履歴を残します。

失敗・期限切れ後に明示的に再撮影する場合だけ、同じアラーム発生回に紐づけて新しい動作指示と制限時間を発行します。進行中のセッションを作り直して期限を延ばすことや、達成済みの権限を再利用することはできません。

## 不正対策の範囲

対策の対象は、未達成のまま解除するAPI呼び出し、他ユーザーの証拠、同じ画像・動画の再送、順序や期限を外れた提出、不完全なAI結果の採用です。元動画のサーバー処理を判定の主な証拠とし、ライブ画像は整合性の補助に使います。

ブラウザ上のコードは利用者が変更でき、仮想カメラや再エンコードで完全一致ハッシュを回避することもできます。ランダムな指の動作とAIの目視推論は、不正がないことの数学的な証明にはなりません。画像の間で行われた動作をすべて確認することもできません。

顔や全身の表示を求めるのは動作の観察のためで、Googleアカウントの本人と映像の人物を照合する生体認証は行いません。また、動画から飲料の化学的成分を証明することはできません。誤判定をゼロとせず、合格例・未達成例の両方で精度を確認する必要があります。

## 保存と削除

D1にはアラーム・アカウント・ミッション結果を継続保存します。動画とフレームは判定・中断後の削除対象です。取り残された証拠は定期清掃で除去します。重複検出ハッシュや受信時刻は別の短期メタデータとして管理します。

D1 BLOBを削除しても、Time Travelなどのバックアップ保持まで即時に消えるわけではありません。「判定後に削除」はアプリが使用する稼働中のデータへの処理を意味します。[D1の復元機能](https://developers.cloudflare.com/d1/reference/time-travel/) とCloudflare側の保持条件を含めて運用してください。

## テストの技術と判定範囲

| 技術 | 採用した理由 |
| --- | --- |
| GitHub Actions | 公開リポジトリへのpushでビルド・テスト・依存関係検査を実行し、他の環境でも再現できることを確認するため。 |
| Prettier | TypeScript・CSS・テストコードの書式を揃え、変更点をレビューしやすくするため。 |
| Vitest | TypeScriptの実装と近い環境で、日時・入力・状態遷移・失敗経路を自動検証するため。仮想時刻を使って待ち時間と時刻境界を再現します。 |
| Node `node:sqlite` | バックエンドのSQL、制約、トランザクションを実SQLiteで実行するため。D1のAPI形状をテスト用アダプターで合わせます。Cloudflare本番ランタイムそのものではありません。 |
| Testing Library / user-event | 内部stateを直接書き換えるよりも、ラベル、ボタン、入力、キーボードから利用者の操作を検証するため。 |
| jsdom | React画面のDOM・フォーカス・アクセシブルな操作をNodeで実行するため。ブラウザの実レンダリングやカメラを再現するものではありません。 |
| カメラ・AI・Mediaのテスト用代替実装 | 権限拒否、切断、遅延、不正なAI応答などを一定条件で再現するため。実モデルの精度を測る用途ではありません。 |
| 実ブラウザの操作確認 | 狭い画面、フリック、アニメーション、ダイアログ、ネットワーク応答を画面から確認するため。Googleログイン・実カメラ・実AIは接続済み環境で追加確認します。 |

`npm test` の成功は、そこで実行したテスト条件の成功を意味します。実機Safari／Chrome、Google OAuth、Cloudflareの動画変換・AIに成功したという意味にはしません。実サービスでの完了報告には、使用端末・ブラウザ、公開先、実施したミッション、成功／失敗例、再撮影とスヌーズの結果を分けて残します。
